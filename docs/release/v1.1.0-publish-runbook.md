# v1.1.0 publication runbook — blocked pending evidence

This is a prospective source document. It can be reviewed and merged while
model release remains **HOLD / NOT_PROMOTABLE**. Source acceptance is not
authorization to run training, tag a release, mint a DOI or upload adapters.

Before any model release, all of the following must be established from exact
source and artifact bindings:

1. The existing source, environment, dataset and leakage contracts admit the
   proposed run. Frozen held data, evaluation-only probes and sealed thresholds
   remain unchanged.
2. Each of seeds 11, 23, 37, 53 and 71 has a verified training receipt and an
   exact adapter binding, plus held-evaluation and red-team evidence from the
   admitted implementation.
3. The refusal gate is earned for every seed: zero false labels on refusals.
   An `EARNED` refusal verdict alone does not establish full release admission.
4. Every other sealed criterion is independently satisfied, including
   calibration and any stratified evaluation required by the existing
   [promotion program](../PROMOTION_PROGRAM.md). Missing evidence stays missing.
5. The current release-receipt verifier and publisher admit the exact candidate;
   no BLOCKED, REFUSED or NOT_ESTABLISHED result is rewritten into promotion.

After those prerequisites and separate release admission:

1. Populate the pending release notes from the verified per-seed evidence,
   retaining failed historical receipts and exact source/artifact identifiers.
2. Review the complete release and its existing GitHub, Zenodo and Hugging Face
   publication effects before creating a tag or release. Verify any resulting
   DOI and provider revision independently; neither follows from a docs merge.
3. Use the existing adapter publisher only if its own leakage and promotion
   checks pass. Do not bypass its refusal or substitute a source-CI result.
4. Update publication records and model-card gate tables only from those
   observed results. Do not pre-fill `12/12` or `PROMOTABLE`.

If a prerequisite fails or remains unavailable, preserve that evidence and keep
the model NOT_PROMOTABLE. Publishing a truthful failure record is distinct from
promoting the model. No execution, tag, DOI or provider write is part of this
source preparation.
